# jabu

Статическая merge-головоломка по `frog-merge-mechanics.md`. HTML, CSS, JavaScript, без зависимостей и сервера приложения.

## Запуск

```sh
npm run dev
```

Открыть http://localhost:5183. Нужны Python 3 и браузер с поддержкой ES modules. Проверка правил: `npm test` (Node.js 18+).

## GitHub Pages

1. Загрузить содержимое этой папки в GitHub-репозиторий, включая `frogs/`.
2. В Settings → Pages выбрать Deploy from a branch, ветку `main` и папку `/ (root)`.
3. После публикации открыть адрес, указанный GitHub Pages.

Сборка не требуется. Все пути относительные: приложение работает и по адресу `username.github.io/repository/`.

## Управление

Перетащить жабу на любую жабу того же уровня либо нажать на двух жаб по очереди. Клавиатура: Tab для выбора клетки, Enter/Space для нажатия. На телефоне поле поддерживает перетаскивание, страница прокручивается за его пределами.

Звук включается после первого пользовательского жеста. Квак воспроизводится из `frog-croak.mp3` через Web Audio API: каждый следующий полученный уровень звучит ниже и дольше за счёт уменьшения скорости воспроизведения. Уровень 2 использует исходную скорость. Кнопка вверху выключает звук. Включите `frog-croak.mp3` при публикации. При ошибке загрузки используется синтезированный квак; внешние сервисы не нужны.

Арты `frogs/1.png`–`13.png` соответствуют уровням. На уровнях выше 13 используется последний арт с актуальным номером. Текущая партия и рекорд очков сохраняются в localStorage после каждого объединения и начала новой игры. Перезагрузка восстанавливает партию, новая игра сохраняет рекорд.

Баланс и начальная раскладка — в `game.js`, оформление — `style.css`, звук — `audio.js`, управление — `app.js`.

## Генерация жаб

Основной спавн всегда остаётся 1/2 с вероятностями 85/15. После открытия 6-го уровня постепенно добавляется редкий спавн старших жаб:

| Открытый уровень | Шанс выбрать старшую пару |
| --- | --- |
| До 5 | 0% |
| 6 | 0,5% |
| 7 | 1% |
| 8 | 1,5% |
| 9 | 2% |
| 10 и выше | 2,5% |

Старшая пара — уровни `max(2, открытый уровень − 2)` и на один выше. Например, на 8-м это 6/7. Внутри обеих пар сохраняются 85/15. Основной спавн мелких жаб остаётся доступен на любом уровне.

Прогрессия зависит от максимального уровня текущей партии и применяется сразу после объединения. Сохранённые партии используют новый баланс без сброса поля и рекорда.

## Автоматический подбор баланса

```sh
npm run balance -- --output /tmp/jabu-balance.json
npm run balance -- --apply --output /tmp/jabu-balance.json
```

Алгоритм перебирает частоту редких старших жаб при фиксированном отставании на два уровня. Для каждого кандидата он строит граф состояний до 13-го уровня и рассчитывает оптимальные шансы достижения 10–13-го. Побеждает вариант с наименьшим отклонением от целевой кривой сложности. Незавершённые расчёты исключаются из выбора. `--apply` записывает выбранные параметры в `game.js`; после этого выполните `npm test`.

## Поиск оптимальной стратегии

```sh
npm run search -- --target 13 --output /tmp/jabu-search
```

Алгоритм перебирает все достижимые состояния поля и все исходы спавна с ненулевой вероятностью. Перестановки клеток считаются одним состоянием: объединять можно любые одинаковые пары. Затем динамическое программирование выбирает ход с максимальной вероятностью достичь цели без знания будущих выпадений.

Результаты сохраняются в указанную папку: `summary.json` — итог проверки, `witnesses.json` — воспроизводимые цепочки объединений с указанными выпадениями, `policy.json` — выбранные ходы для состояний поля. Цепочка при удачных выпадениях не означает гарантированное прохождение. Если цель недостижима, это явно указано в отчёте.

Команда не меняет баланс или сохранённую партию. Для проверки другого баланса нужно изменить конфигурацию в `game.js` и повторить поиск.
