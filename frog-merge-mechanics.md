# Frog Merge — игровая механика (MVP)

## 1. Концепция

**Frog Merge** — бесконечная single-player merge-головоломка на поле **3×3**. Игрок скрещивает двух жаб **одного уровня** независимо от расстояния между ними. Результат — жаба следующего уровня. После скрещивания на освободившейся клетке появляется новая жаба низкого уровня.

Игра не имеет финального уровня или победного состояния: цель — набрать максимум очков и получить жабу максимально высокого уровня. Партия заканчивается, когда больше нет доступных скрещиваний.

## 2. Правила (обязательные)

1. Поле состоит ровно из **9 клеток (3 строки × 3 столбца)**.
2. **Каждая клетка всегда занята одной жабой**. Пустых клеток в нормальном игровом состоянии нет.
3. У каждой жабы есть целочисленный `level >= 1`.
4. Игрок может скрестить **любых двух жаб одинакового уровня** на любых клетках, даже если они не соседние.
5. **Нельзя** перемещать жаб на пустые клетки, менять жаб местами или перемещать их без скрещивания.
6. Нельзя скрещивать жаб разных уровней.
7. При успешном скрещивании жаб уровня `L`:
   - жаба **на целевой клетке** заменяется на жабу уровня `L + 1`;
   - **исходная клетка** немедленно заполняется новой жабой уровня `1` или `2`;
   - начисляются очки;
   - проверяется наличие хотя бы одной пары одинакового уровня.
8. Неудачное действие не меняет состояние поля и не начисляет очки.
9. **Game Over** наступает, когда среди 9 жаб нет ни одной пары одинакового уровня.
10. Ограничения по числу ходов и таймера нет.

> **Важно:** «бесконечная» означает отсутствие заданного последнего уровня или количества раундов, но отдельная партия может закончиться из-за отсутствия пар.

## 3. Управление

### Основное — drag-and-drop

- Нажатие и удержание жабы начинает перетаскивание.
- Перетаскиваемую жабу можно навести на **любую** из остальных восьми клеток; соседство не требуется.
- Подсвечивать клетки с жабами того же уровня как допустимые цели.
- При отпускании над жабой **того же уровня** выполняется скрещивание: `source -> target`.
- При отпускании над жабой другого уровня, исходной клеткой или вне поля — отмена, исходное состояние восстанавливается.
- Во время перетаскивания визуально перемещается только изображение жабы. Состояние игры не меняется до успешного отпускания.

### Дополнительное управление — два нажатия

Для устройств/сред, где drag-and-drop неудобен:

1. Первое нажатие выбирает исходную жабу.
2. Второе на жабу того же уровня выполняет скрещивание.
3. Повторное нажатие на выбранную клетку отменяет выбор.
4. Нажатие на жабу другого уровня переносит выделение на неё **без изменения поля**.

Можно оставить только drag-and-drop, если цель — максимально простой MVP, но для доступности рекомендуется поддержать оба сценария с одинаковым игровым правилом.

## 4. Генерация новых жаб

После **каждого успешного скрещивания** исходная клетка заполняется по вероятностям:

| Уровень новой жабы | Вероятность |
|---|---:|
| `1` | 85% |
| `2` | 15% |

Это **стартовые параметры баланса**, вынести в конфигурацию для быстрой настройки. Новые жабы **не появляются по таймеру, за касания, неудачные действия или произвольные перемещения**.

Начальное поле для прототипа:

```text
1  1  2
1  2  3
2  3  1
```

Для MVP допускается фиксированное стартовое поле выше. Позже можно генерировать случайные стартовые раскладки с гарантией наличия хотя бы одной пары.

## 5. Очки и прогресс

- Скрещивание двух жаб уровня `L` создаёт жабу уровня `L + 1`.
- За скрещивание начислять `10 × 2^L` очков (например, `1+1 -> 2` = 20 очков, `2+2 -> 3` = 40 очков).
- Отображать текущие очки (`score`), количество успешных скрещиваний (`mergeCount`) и максимальный уровень, достигнутый за текущую партию (`maxLevelReached`).
- Для `maxLevelReached` учитывать также жаб на стартовом поле, поэтому в приведённой раскладке начальное значение равно `3`.
- Формула начисления — стартовый параметр баланса, не обязательная часть визуального оформления.
- Уровни жаб **не ограничивать** десятью или двенадцатью: для высоких уровней предусмотреть fallback-спрайт или временный плейсхолдер, пока отдельный арт не готов.

## 6. Модель данных

Минимальное состояние:

```ts
type GameState = {
  board: number[];          // ровно 9 элементов; каждый >= 1
  score: number;
  mergeCount: number;
  maxLevelReached: number;
  status: 'playing' | 'game_over';
  selectedIndex: number | null; // только UI, не участвует в правилах
};
```

Индексация массива — по строкам сверху вниз, слева направо: `0..8`.

Рекомендуется отделить чистую игровую логику от UI. Источник случайности можно передавать как функцию `rng()` для тестирования.

## 7. Алгоритм скрещивания

```ts
function merge(board: number[], source: number, target: number, rng: () => number) {
  if (source === target) return { success: false };
  if (source < 0 || source >= 9 || target < 0 || target >= 9) {
    return { success: false };
  }
  const level = board[source];
  if (level !== board[target]) return { success: false };

  const nextBoard = [...board];
  const newLevel = level + 1;
  nextBoard[target] = newLevel;
  nextBoard[source] = rng() < 0.85 ? 1 : 2;

  const points = 10 * 2 ** level;
  const gameOver = new Set(nextBoard).size === 9;

  return {
    success: true,
    board: nextBoard,
    points,
    newLevel,
    gameOver,
  };
}
```

После успеха UI/контроллер должен обновить `score`, `mergeCount`, `maxLevelReached`, `status` **один раз**, атомарно. Пока анимация скрещивания не закончилась, новые действия блокируются, чтобы одно событие не запустило два объединения.

**Пример:** если перетащить жабу с позиции `0` (уровень 1) на позицию `1` (уровень 1), то позиция `1` становится уровнем `2`, а позиция `0` — новой жабой уровня `1` (85%) или `2` (15%). Все прочие клетки не меняются.

## 8. Game Over

После генерации новой жабы проверить доступность ходов:

```ts
function hasAvailableMerge(board: number[]): boolean {
  return new Set(board).size < board.length;
}
```

Если все 9 уровней различаются, установить `status = 'game_over'`, заблокировать попытки скрещивания и вывести экран с результатом и кнопкой **«Новая игра»**. Кнопка сбрасывает весь игровой прогресс и создаёт стартовое поле.

## 9. Интерфейс MVP

- Крупное центральное игровое поле **3×3** с квадратными клетками.
- В каждой клетке: спрайт жабы соответствующего уровня; на этапе прототипа можно временно использовать один спрайт с разными фоновыми цветами и подписью `LV N`.
- Над полем: текущие очки и максимальный достигнутый уровень.
- Под полем: короткая инструкция/индикатор успешного скрещивания; количество скрещиваний и кнопка **«Новая игра»**.
- Подсветка выбранной жабы и допустимых целей.
- При скрещивании: короткая анимация объединения в целевой клетке и появления новой жабы на исходной; плавный прирост счёта. Анимации не должны замедлять цикл игры чрезмерно.
- Адаптация под мобильный экран и мышь на десктопе.
- Без магазина, валюты, энергии, уровней-карт, бонусов и внешнего бэкенда в MVP.

## 10. Критерии приёмки

1. Поле всегда содержит **ровно 9 жаб** до конца и после окончания партии.
2. Можно объединить одинаковых жаб из двух противоположных углов поля.
3. Жабы разных уровней не объединяются и не перемещаются.
4. Клетки нельзя переставлять местами, а свободного перемещения нет.
5. При `source -> target` уровень на **target** увеличивается на 1, а на **source** появляется уровень 1 или 2.
6. После одного успешного действия начисляются очки и увеличивается счётчик скрещиваний ровно на 1.
7. После отменённого действия поле и все счётчики остаются прежними.
8. Когда девять уровней уникальны, появляется Game Over и новые скрещивания недоступны.
9. «Новая игра» сбрасывает состояние корректно.
10. На сенсорном устройстве и мышью можно провести полноценную партию.
11. Отсутствуют искусственные ограничения по уровню жабы, времени и числу скрещиваний.

## 11. Вне рамок MVP

Коллекция открытых жаб, достижения, глобальный рейтинг, звук, особые способности, реклама, внутриигровая экономика, пользовательские аккаунты и серверное сохранение. Их можно добавлять позже, **не меняя базовое правило скрещивания**.
